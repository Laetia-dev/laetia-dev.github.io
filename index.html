01Master’s thesis · 2026

Perceived Believability and Player Enjoyment: AI-Generated Interaction in Social Deduction Games

A single-player social deduction game powered by three dialogue systems.

I developed this Unreal Engine 5.5 murder investigation game using Blueprints and C++, including randomized hidden roles, NPC interactions, accusations and round transitions. I integrated OpenAI through VaRest, REST requests and JSON, and built data-driven character prompts from NPC profiles, relationships and roles. The research compared keyword, hybrid and LLM dialogue while C++ logging captured interactions and gameplay events. The hybrid system included a planned LLM fallback, which was not triggered during the study.

My role Game architecture, Blueprint programming, AI integration, C++ logging and research

  • Unreal Engine 5.5
  • Blueprints
  • C++
  • REST APIs
  • Research
Game build · OneDrive ↗
Inside the project

Character and role systems

I assembled prompts from character identities, OCEAN personality traits, relationships and the current scene. Unreal Data Tables keep character profiles separate from the roles assigned each round.

Dialogue and integration

The prototype routes questions through authored keyword, hybrid and LLM dialogue conditions. The hybrid LLM fallback was planned but was not triggered in the study. OpenAI responses use VaRest REST requests and JSON, with prompts assembled from character identities, roles, relationships and scene context.

Research data

I used C++ and Blueprints to log conversations, round events and accusation outcomes, then organised the logs and questionnaire responses for analysis. The final dataset contained 29 sessions and 20 questionnaire respondents, including partial responses.

What the study showed

LLM dialogue received the highest average believability and enjoyment ratings. The small exploratory study did not establish an overall significant difference in enjoyment. It compared AI dialogue systems, without live human responders.

02Bachelor’s thesis · 2024

Reliable Player-NPC Interaction with Large Language Models

A configurable Unreal Engine prototype for AI-driven NPC conversations and memory.

For my bachelor’s thesis, I integrated OpenAI GPT and Google Gemini through REST APIs, with configurable API keys and model selection available inside the prototype. I built character-based prompting around ongoing conversation history and persistent NPC memory, using structured summaries to help characters retain context across interactions. The prototype also explored speech input, ElevenLabs voice output and the challenges of keeping generated dialogue consistent.

My role Sole technical development, multi-provider API integration and NPC memory

  • Unreal Engine 5.3
  • Blueprints
  • OpenAI
  • Gemini
  • ElevenLabs
Game build · OneDrive ↗
Inside the project

Voice and API integration

I integrated OpenAI GPT and Google Gemini via REST APIs, parsed JSON responses and exposed user-configurable API keys and model selection. Speech recognition handles player input, while ElevenLabs provides character voice output.

Conversation memory

I implemented both ongoing conversation history and persistent NPC memory. Structured summaries record earlier interactions, including their type, details, outcome and timestamp, so later dialogue can use past context.

Characters in a world

Character prompts include time and schedule information. NPC navigation and the conversation interface connect dialogue to characters in the scene. Environment assembly uses third-party assets.

What I learned

Prompt structure and context can support consistency, but do not guarantee reliable responses. This practical exploration led to my master’s research into how players experience AI dialogue.

03Bachelor semester 6 · Team project

M.S. Balance Experiment

A Unity research environment using visual motion and body movement to investigate balance.

Created with researchers at Lebanese University, this experimental prototype used four-direction leaning controls and moving scenery to provide optic flow. I developed the desert-road visuals, lighting, materials and Substance Designer textures. To make the landscape appear endless, I moved and repeated the surrounding environment while the participant remained relatively stationary. I also implemented part of the control functionality; another teammate integrated the camera tracking plugin.

My role Environment visuals, looping scenery and shared controls programming

  • Unity
  • C#
  • Substance Designer
  • Experimental controls
Game build · OneDrive ↗Source code ↗
Inside the project

My visual work

I worked mainly on the environment visuals and lighting, including desert, road and tree textures. I used Substance Designer to explore material creation beyond my assigned programming role.

Moving scenery

I created a continuous-motion illusion by moving and repeating the surrounding road, trees and desert scenery while the participant stayed relatively stationary. This produced sustained optic flow without requiring a huge environment.

Shared programming

I implemented part of the control functionality alongside the team. Another teammate integrated the camera tracking plugin. The application includes calibration and configurable experiment settings.

Research context

The project was designed as an experimental tool with researchers, including Dr. Hiyam Ibrahim. It supports adjustable sessions and cues. The focus was to give researchers control over the experiment’s conditions.

05Bachelor semester 5 · Individual project

Raspberry Pie, Cookies and Cake

A voice-assisted robot dog and an early exploration of conversational AI.

I assembled and extended a Freenove robot dog using Python and a Raspberry Pi, combining adapted kit functions with my own voice recognition work. The robot responded to spoken movement commands and supported a simple workout-companion concept with counting, camera, face and symbol recognition. Before ChatGPT was publicly released, I researched GPT-2 as a possible conversational extension, but did not implement it. I also experimented with Linux, website hosting and setting up a mail server.

My role Robot assembly, Python development, voice interaction and Linux hosting

  • Python
  • Linux
  • Raspberry Pi
  • Server hosting
Inside the project

Robot and interaction

I adapted the Freenove kit's controls and speech-recognition functions and extended them with my own Python work. The voice-assisted robot responded to movement commands and supported counting, camera, face and symbol recognition. I also investigated GPT-2 as a potential conversational extension, but never integrated it.

Linux and hosting

I mounted a screen and set up two Linux environments for desktop use and game emulation. Hosting work included a website, domain and dynamic DNS setup, plus an email server configured with the help of a tutorial.

Learning through small games

I learned Python through exercises and small games such as Snake and Pong. These experiments gave me a way to apply the language while developing the broader project.

From game controls to hardware

This project connected my interest in unusual game controls with physical hardware. It also gave me hands-on experience assembling, configuring and troubleshooting software and Linux systems.
